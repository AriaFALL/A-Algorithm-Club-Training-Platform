## 三、连签奖励二次复查

### 计算和去重规则

1. 使用北京时间自然日。有效提交日期与签到日期取并集，未来日期不参与。
2. 奖励周期为周一至周日。计算该周内最长连续段，各奖励档位满足条件后结算。
3. 去重键为“团队、用户、该周周一、档位天数”。一周出现第二段同长度连签、删除再恢复配置、成员关系删除后重建，均不会重复领取已存在的同档凭证。
4. 同周不同档位可以分别获得，例如3天+1、7天+2，达成7天时本周合计这两个档位3 Coins，而不是每滑动三天再发一次。
5. 补交成功后重新计算补签所在周。只扣券未提交不计签到，不触发连签奖励；历史补签不补发今日每日签到奖励。
6. 凭证、余额、流水在同一事务中提交。并发只结算一次，入账失败不留下已领取凭证。

| 场景 | 预期及验证结果 |
|---|---|
| 本周两段3连签 | 3天档只发一次 |
| 周日接下周一连续 | 每周分开计算奖励，不能跨周凑档 |
| 补签填平本周中间缺口 | 立即重算该周；新达成档位补发，旧档不重发 |
| 补签上周 | 只核算上周相关新档位 |
| 同日多次有效提交 | 日期一次，每日基础奖励一次 |
| 删除/重建同一天数档位 | 已领凭证继续有效 |
| 同时两个结算请求 | 唯一约束及事务保证一次 |
| 删除再添加成员 | 已有用户级凭证继续拦截同周同档重复奖励 |

签到榜展示当前连续天数：今天未签时允许从昨天向前数，今天已签则从今天数。**榜单连续天数可以跨周；奖励计算按周截断。** 两者含义不同，不能用榜单天数直接重复派发每周奖励。

## 四、难度、年级与比赛AC奖励

### 分档规则

大一上为萌新，其余为老登。年级仅注册时选择，每年2月15日、8月1日递进，大三+封顶。奖励以比赛开始日的年级判定，避免以后领取改变历史比赛适用组别。

| 平台 | 难度来源 | 萌新：第二/第三档起点 | 老登：第二/第三档起点 |
|---|---|---:|---:|
| LeetCode（中国/国际） | zerotrac统计题目Rating | 600 / 1200 | 1000 / 1500 |
| Codeforces | 官方题库Rating | 1000 / 1600 | 1400 / 2000 |
| AtCoder | AtCoder Problems模型难度 | 400 / 1000 | 800 / 1600 |
| 牛客 | 官方Tracker题目difficulty | 1100 / 1600 | 1600 / 2100 |
| 洛谷 | 官方难度等级 | 2 / 4 | 4 / 6 |

低于第二档起点是第一档，达到第二档且低于第三档是第二档，达到第三档是第三档。默认各组金额为1/2/3 Coins，系统管理员可分别配置两组三档金额，0表示关闭该档。上述跨平台阈值为项目适配规则，不宣称各平台难度存在官方精确等价关系。

例如LeetCode Rating800：萌新第二档、老登第一档；默认分别2/1 Coins。Rating1300：萌新第三档、老登第二档；默认分别3/2 Coins。全部平台的边界、不同组和自定义金额已测试。

AtCoder原始模型低于400时按`400 * exp((difficulty - 400) / 400)`换算；洛谷0、负数、非有限数或缺失值不冒充有效难度。**未取得难度时保留原最低档策略，不虚构Rating，已领取后不自动补差。**
