# 比赛日程、进度与奖励（现行规则）

更新日期：2026-10-29。本文以本轮最后确认的“AC 时间无法核验时宽松兜底”要求为准。

## 日程读取与更新

- 支持 Codeforces、AtCoder、牛客、洛谷、LeetCode；不接入 QOJ/HDU。
- `GET /api/contests` 只读数据库中的各平台快照，展示未来90天和最近结束7天。
- Celery Beat 每日北京时间06:00、18:00调用 `club.tasks.refresh_contest_calendar` 异步更新。
- 手动“刷新日程”调用 `GET /api/contests?refresh=1`，沿用成功15分钟、失败60秒的共享缓存间隔。
- 各平台更新失败保留最近成功数据及更新时间。重启Web/Worker不会清空快照。
- 首次部署可执行 `club.tasks.refresh_contest_calendar.delay()` 异步初始化；正常页面访问不触发外站抓取。
- 日程任务优先级0、资料同步优先级2、其他任务默认5，Worker预取1；正在执行的长任务仍可能造成延迟。

## 个人资料与平台凭据

- 个人资料页供团队管理员和普通成员使用，昵称按团队保存，头像及平台绑定在同一用户的团队间共享。
- 年级仅在注册时选择；2月15日、8月1日自动晋级，大三+不再晋级。个人页只读展示年级。
- 大一上为萌新，大一下及以后为老登；比赛奖励按比赛开始时的年级判断。
- 洛谷Cookie由系统管理员在管理工作台统一配置，加密存储，不回显；不要求每个用户配置，也不要求Cookie所属UID与被查询UID一致。
- API `GET/PUT /api/management/platform-query` 仅系统管理员可用，GET只返回是否已配置。
- 平台绑定是公开账号关联，不是账号所有权认证。现行流程没有新增所有权挑战或第三方登录。

## 已参加比赛与操作

- “同步比赛进度”触发异步历史发现和逐场核验。旧数据在失败时保留。
- “已参加”不受日程展示的最近7天窗口限制。
- 点击比赛卡片，题目托盘从卡片下方展开，题号保持单行，可横向滚动。
- AC题目标绿；待领奖题号使用加强抖动，收起时比赛卡片沿用原抖动。
- 系统减少动态效果设置会关闭这些动画。
- 单题领取浮现币数量；多题可一键领取并汇总结果。
- 重复投递的逐场任务不重复扣减剩余数量，持续有进展的长历史同步不会因最初请求已超过30分钟而误判超时。

## 时间核验与宽松兜底

1. 比赛开始时间必须不早于北京时间2026-11-01，比赛已经开始，当前账号仍绑定该参赛账号。
2. 必须有可靠的具体题目AC证据，不能将参赛名次、总过题数或空接口响应当作该题已AC。
3. 有有效作答时间时，只认可 `比赛开始 <= AC时间 < 比赛结束`；未来时间、明确赛外/非正式记录不奖励。
4. **已确认AC但作答时间缺失或无法核验时，统一宽松发奖。** 这一分支也不再因整体时间核验未完成而阻挡已有可靠AC的单题。
5. 洛谷时间查询失败时可使用已确认的公开AC清单兜底；已经取得的明确赛外记录不会被改写成“时间未知”。
6. 缺少AC证据仍不奖励。AtCoder镜像为空会显示“暂无法完整核验”，不能因此将所有题标为AC。
7. 领取接口统一执行这些判断，前端标志和直接请求使用同一底层规则。

接口同时返回 `accepted`、`official_ac`、`timing_relaxed`、`claimable`、`reason`，分别表达AC证据、已证实的正式AC、时间宽松兜底、当前可领与阻止原因。时间兜底领取在币流水中明确标注。

## 题目难度与分档

| 平台 | 难度来源 | 萌新第二/第三档起点 | 老登第二/第三档起点 |
|---|---|---:|---:|
| LeetCode 中国/国际站 | zerotrac统计题目Rating | 600 / 1200 | 1000 / 1500 |
| Codeforces | 官方题库Rating | 1000 / 1600 | 1400 / 2000 |
| AtCoder | AtCoder Problems统计模型 | 400 / 1000 | 800 / 1600 |
| 牛客 | 官方Tracker题库difficulty | 1100 / 1600 | 1600 / 2100 |
| 洛谷 | 官方难度等级 | 2 / 4 | 4 / 6 |

这些是本项目既定平台适配阈值，不是各平台官方宣称的等价换算。小于第二档起点为第一档；大于等于第二档、小于第三档起点为第二档；其余为第三档。默认两类金额均为1/2/3 Coins，可分别配置六个数值，配置0表示该档关闭。

AtCoder低于400的原始模型值按 `400 * exp((difficulty - 400) / 400)` 处理。洛谷0/缺失表示无评级；牛客未知值不伪装成有效Rating。未取得难度仍沿用最低档策略，不编造Rating，领取后不自动补差。

## 去重、隔离与演示数据

- 发奖与币流水处于同一数据库事务；失败回滚。
- 同团队、同用户、同平台、同比赛、同题只能领取一次；同团队、同平台账号、同比赛、同题也只能领取一次。
- 单题与一键领取并发不会重复发放；解除/重绑、删除/重建成员关系不会重置已领凭证。
- 普通用户及团队管理员按当前团队权限领取，系统管理员为管理预览，不参与个人领奖。
- 演示账号仅在指定演示团队允许模拟比赛时钟；公共API不能写入演示标志，真实比赛不使用此例外。
