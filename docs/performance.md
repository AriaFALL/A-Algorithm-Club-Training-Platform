# 数据库访问优化（2026-10-08）

本次保持接口、页面、审核权限、计分、截止时间和归档规则不变，不新增缓存或数据库迁移。

## 改动

- `build_weeks` 一次读取已有周次，仅在缺失时批量补齐；并发创建通过已有唯一约束去重，不覆盖已有日期、结算状态或周次规则。
- `refresh_totals` 在调用方已有的学期事务锁内批量更新成员汇总，保留姓名快照、更新时间和归档保护。
- 学期列表预取周次，避免每增加一个学期就多一次查询。

## 验证

在独立 PostgreSQL 16 测试容器中执行 `python manage.py test club --noinput`，42 项测试全部通过，包含并发审核、并发审核与归档、并发补齐周次，以及新增的查询次数和结果一致性检查。

与提交 `7e8fb88` 的实现对比：40 名成员、20 个已关闭周次、已有完整周次的合成场景中，统计 SELECT / INSERT / UPDATE / DELETE，不计事务控制语句：

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 检查并读取完整周次 | 21 | 1 |
| 刷新全体成员学期汇总 | 124 | 45 |

对比场景中的周次及汇总业务字段一致；非零积分、待审核和无效提交排除、姓名更新、周次达标和归档结果由回归测试覆盖。上述数字是数据库访问次数，不等于页面延迟或服务器容量的压测结论。

## 部署

按现有方式重新构建并更新 Web、Worker、Beat 服务即可应用本次代码改动，无需额外迁移。不要改变现有部署使用的 Compose 项目名。

## 第二轮优化

在第一轮提交 `d1997f3` 基础上，将成绩统计扩展为按周次和成员分组，一次返回全学期成绩。学期汇总复用分组结果，首页的周次状态和连续达标统计共享一次个人成绩读取，避免逐周查询。

未结算周仍计入学期累计成绩，仅已结算周计入达标周数；连续达标统计沿用原有规则。周次独立阈值、零分阈值、无效提交排除和权限过滤均保持不变，不引入跨请求缓存。

独立 PostgreSQL 16 测试环境中，46 项测试全部通过，包含新增的分组结果与逐周结果一致性、筛选范围、未结算周、零阈值、单周规则和首页统计检查。
